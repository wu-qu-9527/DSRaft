# Checksum 生成与校验

持久化文件采用带版本和 FNV-1a 校验和的 JSON。三种文件共用
[json_record.cpp](../src/server/storage/json_record.cpp) 中的编码与校验逻辑，
算法实现在 [binary_codec.cpp](../src/common/binary_codec.cpp)。

## 1. JSON 记录

正式文件为 `state.json`、`log.json` 和 `commit.json`，均包含以下字段。

| 字段 | 内容 |
| --- | --- |
| `format` | 分别为 `raft-state`、`raft-log`、`raft-commit` |
| `version` | 当前为整数 1 |
| `data` | 对应存储的数据对象 |
| `checksum` | 64 位无符号整数形式的 FNV-1a 校验和 |

状态数据包含 `current_term` 和 `voted_for`，未投票使用 `null`。
提交检查点包含 `index` 和 `term`。
日志数据包含 `entries` 数组，每个条目包含 `index`、`term` 和命令。
UTF-8 命令使用 `command`，含非法 UTF-8 字节的命令使用 `command_hex`。

所有 uint64 字段都进行类型和范围检查，支持 18446744073709551615。
负数、小数、布尔值和数字字符串会被拒绝。

## 2. 校验范围

计算前移除 `checksum` 字段，对剩余完整对象调用 nlohmann/json 的默认 `dump()`，
得到对象键按字典序排列、没有格式化空白的 UTF-8 字节，再计算 FNV-1a。

例如任期为 7、投票给节点 42 的输入字节如下。

```json
{"data":{"current_term":7,"voted_for":42},"format":"raft-state","version":1}
```

FNV-1a 从 14695981039346656037 开始，对每个无符号字节依次进行异或和乘法。
乘数为 1099511628211，uint64 运算自然按模 2^64 回绕。

```cpp
std::uint64_t value = 14695981039346656037ULL;
for (unsigned char byte : bytes) {
    value ^= byte;
    value *= 1099511628211ULL;
}
```

格式标识、版本和数据均参与校验。正式文件使用两空格缩进并以换行结尾，
读取时重新解析并生成紧凑表示，因此缩进、换行和对象字段顺序的变化不会影响校验。
修改字段值需要重新生成校验和。

## 3. 保存与恢复

保存时先生成数据对象、格式标识和版本，计算校验和后写入 JSON。
随后写临时文件、同步文件、原子替换正式文件，再同步目录。
临时文件继续使用 `state.tmp`、`log.tmp` 和 `commit.tmp`。

恢复时依次检查 JSON 语法、重复字段、格式和版本、校验和、业务字段类型及业务约束。
JSON 嵌套深度限制为 64，超过限制会抛出存储错误。
日志仍需满足索引从 1 连续递增、任期为正且不递减。
提交检查点仍需满足索引与任期同时为零或同时为正，并由服务端校验其对应的日志条目。

校验失败抛出 `StorageError`，服务端停止相关协议处理并退出。
未完成的临时文件不参与恢复。

## 4. 使用示例

调用方仍通过存储接口保存和读取数据。

```cpp
#include "server/storage/state_storage.hpp"

using namespace zmq_template::server;

StateStorage storage{"./data/checksum-example"};
storage.save({7, 42});
const PersistentState state = storage.load();
```

示例会生成可直接查看的 `state.json`。正常启动恢复时直接调用 `load()`，
由状态存储负责读取和校验。

## 5. 校验能力

FNV-1a 用于检测意外损坏，存在碰撞可能。它不能修复数据、认证写入者、
判断完整记录是否被回滚，也不能证明某条日志已被多数提交。
可靠保存依赖临时文件、原子替换、文件同步和目录同步。
提交与恢复边界由 Raft 日志和独立提交检查点共同确定。
