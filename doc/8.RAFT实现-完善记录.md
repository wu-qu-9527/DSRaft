# Raft 完善记录

## 独立配置投票超时

新增 `--vote-timeout-ms MS`，默认 100ms，取值为正整数。它独立于心跳 RPC 超时和随机选举超时。
例如在投票往返延迟可能超过 100ms 的环境中，可配置：

```sh
./build/debug/zmq_server --vote-timeout-ms 500 --heartbeat-timeout-ms 500 \
  --election-timeout-min-ms 1000 --election-timeout-max-ms 2000
```

应为网络、授票落盘和调度延迟保留余量。增大选举超时本身不会延长单次 RPC 的等待时间。

## 在状态变更前拒绝非法 RPC

RequestVote 要求任期、候选者 ID 为正，空日志的索引和任期同时为零，非空日志的末条任期不能超过请求任期。
AppendEntries 同样要求任期、Leader ID 为正。编解码边界统一校验；非法网络输入返回协议错误，
不会先修改任期或投票，也不会因保存非法节点 ID 而触发存储故障退出。

## 客户端请求去重

新增消息类型 `client_request=8`，负载和对应日志命令使用版本化封装：5 字节 `NUL + RQC1`、
8 字节请求序号、8 字节客户端 ID 长度、ID 字节、业务命令；整数使用网络字节序。
ID 长度为 1–128 字节，请求序号必须为正。旧 `text` 请求保持兼容，但不提供安全重试保证。

状态机保存每个客户端最近一次序号、命令和结果。相同序号和命令返回缓存结果；相同序号不同命令、
或者小于最近序号的请求返回确定性错误，不修改业务状态。去重信息随日志复制并在重启重放时恢复。
每个客户端 ID 必须串行提交请求：收到确定结果后再增加序号；不同并发请求流使用不同 ID。
目前会话没有自动过期，避免在客户端重试时静默丢失去重保证。

## 客户端发现 Leader 与重试

普通客户端请求现在使用去重封装；网络超时、非 Leader 和领导权变化时，在总时限内轮询端点并重建 REQ socket，
每次尝试保留相同的客户端 ID、请求序号和命令。默认总时限 10 秒、每次尝试 500ms，可分别通过
`--timeout-ms` 和 `--attempt-timeout-ms` 修改。`--all` 保留逐节点观察模式，不自动重试。

```sh
./build/debug/zmq_client --cluster tcp://127.0.0.1:5555,tcp://127.0.0.1:5556,tcp://127.0.0.1:5557 \
  "SET key value" --client-id example-session --request-seq 1
```

未显式指定 ID 时生成随机 ID，并在请求发送前输出 `client_id` 和 `request_seq`。进程退出且结果未知时，
手动重试必须复用输出的 ID、原序号和原命令；确认结果后才增加序号。直接重新启动并使用新随机 ID 会成为新请求。
端点列表需要包含可到达的新 Leader；当前通过轮询发现，不依赖将节点 ID 猜测成地址。

## 网络故障测试

`tests/network_test_helpers.hpp` 提供每条有向连接独立的代理，可丢请求、丢响应或延迟响应。
进程级测试保持旧 Leader 存活，将网络切成 2+1 后验证少数侧不能提交、多数侧换主并写入，
恢复后旧 Leader 退位且冲突后缀被修复；另覆盖单向丢响应时多数仍能推进。
协议测试覆盖重复追加及较旧任期消息延迟到达后不能覆盖已提交历史。
